N46 is a separate local-fork regression found during N45 review; it claims no upstream commit mapping.

The observed local feature and D0 share the same backup.py blob. Its `_collect_memory_provider_external_paths()` body references an unbound `include_missing`, so `hermes backup` raised NameError as soon as an active provider declared an external path. `hermes import` called the same no-argument helper with `include_missing=True`, raising TypeError for a valid external member. These are actual backup/import caller failures, reproduced by two RED native tests at the N45 parent. U1's final external restore accepts any home-confined external member, whereas the fork additionally requires an active provider-declared root; replacing the fork path with U1's broader authorization would weaken that boundary.

The helper now declares keyword-only `include_missing=False`. Backup therefore uses existing provider paths only. Import can admit an absent destination root only when the active provider declares it, while existing home confinement and `_is_allowed_external_target()` checks remain in force. The new tests use an inert provider and temporary home to exercise both actual callers, archive membership, and the home-relative restore target.
