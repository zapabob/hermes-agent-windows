## Source, caller, and RED

The D0-derived resolver in `tools/mcp_tool.py:1036-1057` used to set the parent process's `os.environ['PATHEXT']` to one MCP server's configured value, call `shutil.which`, and then restore the old value. Another Gateway thread could read or inherit that configured value during the lookup. The real stdio caller builds a filtered child environment before resolution and forwards the result to `StdioServerParameters` at `tools/mcp_tool.py:3268-3313`. U1 moved the retry into a pure helper in `tools/mcp_tool_config.py:136-162`; that split module does not exist in this fork's integration source.

On product parent `13a8077deed19e91d58d5c34bb2d62ce0b4b360d`, a synchronized test held the old retry at its second `shutil.which`. A concurrent reader saw `.CMD` in process-global `PATHEXT`, although the parent value was `.EXE`. The first pure-helper implementation passed that test but searched cwd when child `PATH=""`, and ignored `NoDefaultCurrentDirectoryInExePath=1`. Both cases were RED on native Windows Python 3.12. Local `shutil.which` source and `_winapi.NeedCurrentDirectoryForExePath` confirmed that `path=""` is a miss and that the Windows policy can suppress implicit cwd search. The helper was adjusted to preserve those local semantics; this deliberately avoids copying U1's unconditional cwd insertion.
