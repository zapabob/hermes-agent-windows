## Source and observable contract

The D0 scanner entry points are `downstream/security/engines.py` (blob `0e59d6aa607f83625d10ff1f2b0e361aa7944424`), `downstream/security/service.py` (blob `6d61026b090c6153d4e0b84e3e636db68d60cc70`) and `downstream/security/store.py` (blob `645ba90324a0067493b13ac3fd07205fc1aa7442`). The integration predecessor already carried the local LM01–LM05 and T15/T16 work, so this change builds on that source rather than declaring those contracts unimplemented. `SecurityService.scan_paths` owns bounded submission and cancellation; `_scan_file_reserved` owns the exact source snapshot and policy decision; ClamAV and YARA own definition-bound findings; `SecurityStore` owns durable cache invalidation and epoch checks.

The N05 patch bounds pending futures and waits for running workers after cancellation. ClamAV and YARA check the definition/rule generation around scanning, preserve a confirmed positive when a definition changes or diagnostics are truncated, and keep scanner faults typed. YARA's compiled state is synchronized and tied to a rule-content manifest; same-stem rule collisions and partial compile failures cannot make an old CLEAN result eligible. SQLite migration serializes column inspection with `BEGIN IMMEDIATE`. The cache stores a validity generation and rejects an older CLEAN writer after a failed scan. Because static heuristics use the original suffix and directory, cached findings from identical bytes at a different path are re-scanned when that engine participates. Content-only engines retain cross-path cache reuse.
