Strict callers read current user and managed files each time through the same canonical normalization, environment expansion and managed-leaf precedence pipeline. Strict reads bypass warmed caches, never write or create directories, and report typed path/category errors without YAML source values. Missing or valid empty files are permitted; a missing named profile, unreadable file, malformed root or invalid normalization is refused. Strict fallback to last-known-good is prohibited.

Each invocation captures the caller's canonical HOME before scheduling. Native provenance is retained per caller HOME across discovery, registration, adoption and transport shutdown, so removing a previously native name cannot authorize a cached connection as an explicit server.
