## Failure phases

CLI and API child creation precede parent end. A failed create leaves the original live and unflushed at the CLI create boundary. Later CLI yolo transfer and agent synchronization retain their existing phase-specific failure effects; a failure after selection publication must not be described as a rollback or successful branch.

Gateway external thread creation precedes the DB child. A thread returned before marker persistence or DB creation fails is reported with its identity; the handler does not retry silently or invent deletion authority. Transcript or title persistence remains best effort, but an incomplete copy/title result reports a degraded outcome without a completed-copy count. Destination materialization or switching failure reports the created identities and an unconfirmed binding, rather than claiming a transaction rollback or confirmed original selection. The preexisting crash-gap routing test keeps all birth/origin assertions and uses a dedicated BaseException to distinguish simulated process death from a caught operational RuntimeError; it is not a real process-kill test.

Explicit reply metadata carries authentic logical platform, source scope/author and chat type from delivered relay sources. Unknown scope/author stays unknown. Draft namespaces include source identity so a placement-only final, a legacy final or a concurrent tenant cannot seal another source's stream. Native adapter probes retain their one-argument ABI, while signature selection occurs before invocation; a metadata-aware probe body TypeError fails closed and is never retried without source identity. Existing scoped handoff callers participate in the same compatibility and regression review.
