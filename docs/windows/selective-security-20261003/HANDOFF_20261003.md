## 公開・運用の受入

mainのfast-forward前後で既存tracked WIPのhashと未追跡ファイルのmetadataを照合する。対象を明示してcommitし、forceを付けずorigin/mainへpush、remote refのSHAを照合する。CIは当該SHAの実状態を記録し、pendingを成功としない。

Desktopはcanonical checkoutのpackaged Hermes.exeについてPID・birth・実行ファイルを照合して停止する。別アプリやllamaの子は停止しない。apps/desktopでnpm run packを実行し、install-stampのcommitとdirtyを記録する。既存primary WIPは残るためdirty=trueを正常な証拠として明示する。canonicalのexeを起動し、応答する可視ウィンドウとElectron所有backendを確認する。

Goは実管理者のoperator guardとlockのrepo/exe/birth/同一handle検証を保持して再起動する。今回だけembedding引数を付けず、Goからllamaの起動・再起動を行わない。本番設定ファイルは変更しない。このGoプロセスではembedding supervisionが無効で、次回通常ランチャーでの再起動時に設定が再適用される。変更済みprimaryランチャーの広いStop分岐やstack全体停止は使用しない。

実行結果はdelivery-ledger.jsonと追補に記録する。再起動、build、push、CIの各結果を混同しない。
