# توجيه التنفيذ بحسب المراحل

[بروتوكول الوكلاء](../AGENT_PROTOCOL.md) · [حالة التنفيذ](../STATUS.md)

<!-- routing-not-moa -->
يُسنِد إطار Hermes الأب نموذجاً يوافق عليه المشغّل إلى كل مرحلة: التخطيط ثم التنفيذ ثم إعادة التخطيط.
هذه الآلية ليست MoA وليست تبديل المزوّد عند الفشل. يمكن ضبط أي مزوّد ونموذج يدعمهما المضيف.
إذا تعذّر استخدام المسار المحدد، يتوقف التنفيذ بدلاً من الانتقال بصمت إلى نموذج آخر.

<!-- credentials-host-only -->
تبقى المصادقة لدى الإطار الأب. يُمنع تمرير مفاتيح API أو رموز OAuth أو العملاء المصادق عليهم
أو ترويسات المصادقة أو مسارات مخازن بيانات الاعتماد إلى الوكلاء والعمليات التابعة، بما فيها الأحفاد.
يتحقق المضيف من تصريح التنفيذ المرتبط بالعملية قبل كل مرحلة وقبل التحقق.
عند غياب الحد الأمني أو سحب التصريح، يجب رفض التنفيذ.

<!-- not-os-sandbox -->
لا تنسخ دالة إعداد البيئة بيئة العملية الأب، وتوجّه اكتشاف بيانات الاعتماد إلى مسارات خاصة فارغة.
لكنها ليست عزلاً على مستوى نظام التشغيل. يجب على المضيف عزل الوصول إلى الملفات والذاكرة
وسلاسل المفاتيح وهويات الشبكة والمقابض الموروثة، والتحقق من ذلك في البيئة الأصلية.

<!-- native-adapter-unavailable -->
هذا الفرع لا يوفّر بعد تنفيذاً حياً باستخدام النماذج. المهايئ الأصلي ونقطة التشغيل والتحقق المحمي
واختبارات قبول التكامل الكامل غير مكتملة. لا يجوز اختلاق تصريح أمني لتمرير التنفيذ.
إضافة الإعدادات وحدها لا تفعّل إضافة. نجاح اختبارات المكوّن لا يعني نجاح التحقق من الإطار بأكمله.

تظل `planner` و`worker` و`reviewer` و`SUCCEEDED` و`BLOCKED` و`CANCELLED` معرّفات ثابتة للبروتوكول.
تتوفر الرسائل بالإنجليزية واليابانية والصينية المبسطة والتقليدية والعربية من اليمين إلى اليسار.
تُستخدم الإنجليزية للغات غير المعروفة.
